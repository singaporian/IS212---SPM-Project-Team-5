# US-006 / US-019 / US-033 / US-018 automated coverage

## Testing strategy and PR scope

Browser E2E proves the critical happy path through the real Vue app, HTTP API and PostgreSQL. Unit and integration tests cover detailed rules, invalid inputs, authorization, boundaries, rollback and concurrency. Frontend component tests are a separate layer, not browser E2E.

This PR extends the existing SMOKE-01 rather than creating a second overlapping journey:

Organiser submits an event -> Coordinator Lead assigns a Coordinator -> Coordinator reviews/approves the event -> Coordinator requests a venue -> Venue Staff reviews/approves the booking -> the same Venue Staff adds one internal note -> browser reload -> the note is still visible.

The existing SMOKE-01 continuation through technical arrangements, safety approval, venue preparation and attendee registration is retained. The new note step is performed on the booking created and approved through that journey; it is not bypassed by inserting a separate approved booking fixture.

New standalone browser rejection, alternative, ownership, note-edit/delete and detailed review/conflict scenarios have been removed. These remain covered by existing integration/component tests. No production rule is changed.

## Traceability

| Story | Critical happy-path evidence in SMOKE-01 | Detailed integration evidence retained |
|---|---|---|
| US-006 | Organiser submits the current form directly and sees confirmation; the request reaches the Lead assignment queue. | `backend/test/integration/submissions.test.js`: mandatory validation, current values, stable ID, draft/optional values, Lead-only notifications, rollback and duplicate/concurrent retries. |
| US-019 | Venue Staff opens the submitted booking from the pending inbox on its dedicated review page before approval. | `backend/test/integration/booking.review.test.js`: full request/venue details, operating information, availability/unavailability, recorded buffers, refresh/no writes, authorization and failures. |
| US-033 | Venue Staff approves the pending request and the same booking is saved as approved. | `backend/test/integration/booking.decisions.test.js`: approve/reject/alternative details, Coordinator receipt, attribution/time, stale conflicts, buffers, holds, notification atomicity, invalid input and authorization. |
| US-018 | Venue Staff adds an internal note to that approved booking in the calendar; after a real page reload and reopening the card, the note remains visible. | `backend/test/integration/booking.notes.test.js`: approved/confirmed eligibility, persistence, trusted author/time, order, role restrictions, creator-only editing/deletion, cross-booking note IDs, rollback and deletion isolation. |

SMOKE-01 is a workflow check, not a claim of complete browser coverage of every AC. The application grants Venue Staff role-wide venue access; per-venue staff-assignment isolation is not claimed.

## Teammate coverage preserved

- Existing SMOKE-02 (conflicting approval preserves both bookings) is unchanged from the PR base. Only this PR's added detailed conflict assertions were removed.
- Existing SMOKE-03 (approved change flags arrangements) is unchanged from the PR base.
- The US-021, US-031 and US-032 story-specific Playwright files are untouched. They were inspected to avoid adding overlapping cases.
- The safe cleanup helper in `e2e/support/db.js` is retained: it finds browser-submitted fixture events and removes their broadcast notifications before deleting fixture events/users, leaving other records alone.
- The extra US-018 cross-booking integration assertion is retained: PATCH/DELETE with an existing note ID under a different booking URL return 404 and do not change that note.

## Commands

From the repository root:

```powershell
cd backend
node --test test/integration/submissions.test.js test/integration/booking.review.test.js test/integration/booking.decisions.test.js test/integration/booking.notes.test.js
cd ../e2e
npm run lint
# Only the refined critical happy path:
npx playwright test tests/smoke/pipeline-smoke-journeys.spec.js --grep SMOKE-01
# All three retained smoke tests, including unchanged teammate regressions:
npm run test:smoke
```

Prerequisites: installed backend/frontend/E2E dependencies, Playwright Chromium (`npx playwright install chromium`), PostgreSQL and initialized schema. Playwright starts the real backend/frontend if their ports are free. Do not reseed during execution. Existing CD discovers the smoke tests without a workflow change.
